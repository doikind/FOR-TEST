## Purpose

围绕同一个真实市场洞察，结合爆款拆解的洞察与结构模板，生成至少 3 条原创英文 X 候选内容；每条候选包含内容角度、目标互动行为、英文正文、Hook 说明、内容结构、CTA、事实来源、风险提示与相似度检查结果，并写入待审核池与资产库草稿。

## ADDED Requirements

### Requirement: 基于真实洞察生成多条原创候选
系统 SHALL 围绕同一个真实市场洞察（源自热点事件或用户指定选题）生成至少 3 条原创英文 X 候选内容；候选 MUST 覆盖不同内容角度（如解读型、数据型、观点型），每条候选 MUST 包含：内容角度、目标互动行为、英文正文、Hook 说明、内容结构、CTA、使用的事实来源、风险提示与相似度检查结果。

#### Scenario: 生成三条候选
- **WHEN** 用户基于某真实市场洞察触发二次创作
- **THEN** 系统生成至少 3 条原创英文候选，每条完整展示角度、互动目标、正文、Hook、结构、CTA、来源、风险与相似度

#### Scenario: 候选差异化
- **WHEN** 候选内容与对标内容文本相似度过高
- **THEN** 系统标记相似度风险并建议改写方向

### Requirement: 内容风格与原创性
候选内容风格 SHALL 为专业、简洁、有数据依据、有开发者或产品视角；MUST NOT 做空洞的 AI 宣传，MUST NOT 照搬对标账号原句；每条候选 MUST 引用其使用的事实来源。

#### Scenario: 风格检查
- **WHEN** 用户查看候选正文
- **THEN** 正文体现专业简洁、数据依据与产品视角，且标注使用的事实来源

#### Scenario: 原创性约束
- **WHEN** 候选包含与对标内容高度相似的连续表达
- **THEN** 相似度检查标记该风险，系统提示改写

### Requirement: AI 生成 Provider 抽象与缓存
系统 SHALL 将 AI 内容生成封装为独立 provider 接口，与业务管线解耦；MUST 支持：无 API Key 的 Demo 模式（使用缓存输出或模板）、真实输入对应的缓存 AI 输出加载、可选的 OpenAI 兼容 API 适配层；缓存 AI 输出 MUST 明确标注为缓存结果，不得冒充现场实时模型调用；无 API Key 时，采集、去重、评分、风险检查、审核与存储功能 MUST 仍能真实运行。

#### Scenario: 无 Key Demo 模式
- **WHEN** 应用未配置 API Key 且用户触发生成候选
- **THEN** 系统通过缓存或模板模式产出候选，并在 UI 标注"缓存/模板模式"而非现场模型调用

#### Scenario: 有 Key 增强模式
- **WHEN** 应用配置了 OpenAI 兼容 API Key 且调用成功
- **THEN** 系统使用实时模型增强生成，并标注生成方式

#### Scenario: 缓存命中
- **WHEN** 相同输入已存在缓存 AI 输出
- **THEN** 系统直接返回缓存输出并明确标注"AI 输出缓存"，不重复调用模型

#### Scenario: 模型调用失败回退
- **WHEN** 模型调用失败或超时
- **THEN** 系统回退到缓存/模板模式并提示降级原因，管线其余功能不受影响

### Requirement: 候选进入统一闭环
系统 SHALL 将二次创作候选写入待审核内容池（来源标记为 content_creation）与内容资产库（状态 draft），与热点候选共用同一人工审核流程；HIGH（Blocked）风险候选 MUST NOT 进入内容资产库。

#### Scenario: 候选入池与入库
- **WHEN** 二次创作生成完成
- **THEN** 候选同时出现在待审核池与资产库草稿列表，状态为 draft/pending，来源为 content_creation

#### Scenario: Blocked 候选禁止入库
- **WHEN** 某二次创作候选风险等级为 HIGH
- **THEN** 候选可进入待审核池查看，但禁止进入资产库草稿
